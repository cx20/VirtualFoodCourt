# たべもののつくりかた（VirtualFoodCourt）

コードで料理をつくる技術ノート — [Babylon.js](https://www.babylonjs.com/) による手続き的モデリングの学習サイト。

3Dモデルファイルも写真も **1枚も読み込みません**。点の座標を計算で並べ、焼き色をその場で1ピクセルずつ描き、
たれの濃さを「厚み × 吸収係数」から解く。そうやって作った料理 13 本のサンプルと、
それを中学生・高校生向けにほどいた全 18 章の解説で構成しています。

必要な数学は sin・cos、座標、比例、指数関数（`exp`）、それに少しのベクトル（内積・外積）。
高校1年までの内容でだいたい追えます。

姉妹編に **[やさいのつくりかた（VirtualVegetablePlant）](https://github.com/cx20/VirtualVegetablePlant)** があります。
第I部（01〜11章）はほぼ共通の内容なので、どちらから読んでもかまいません。
料理でしか出てこない話は第II部（12〜17章）にまとめてあります。

---

## まず動かす

サンプルは [Babylon.js Playground](https://playground.babylonjs.com/) 用の形になっています。
インストールは何も要りません。

1. [playground.babylonjs.com](https://playground.babylonjs.com/) を開く
2. 左側のコードを全部消す（`Ctrl`+`A` → `Delete`）
3. [samples/トースト.js](samples/トースト.js) の中身を全部コピーして貼る
4. **Run**（`Alt`+`Enter`）

数秒〜十数秒待つと、皿の上にトーストが出てきます。詳しくは `start.html`（00 まず動かしてみる）を参照してください。

サイト内の `zukan.html`（図鑑）からは、Playground へ行かずにその場でサンプルを実行することもできます。

## ローカルで開く

`file://` でも一応動きますが、ソースビューアとサンプル実行は `assets/src/` の複製（ビルド生成物）に頼る形になります。
HTTP で開くのが確実です。

```sh
cd VirtualFoodCourt
node tools/build.js          # HTML 全ページと assets/src/ を生成
npx serve .                  # 任意の静的サーバでよい
```

### 色について

`assets/site.css` の顔料（`--p-kitsune` など）は、すべて**サンプルのコードに実際に書かれている値**を
sRGB 0-1 → 16進に直したものです。出典をコメントに残してあります。

```css
--p-kitsune:#E09B53;  /* トースト.js CBR2 [0.878,0.608,0.325] きつね色 */
--p-sauce:#58250E;    /* たこ焼き.js saucePool [0.345,0.145,0.055] ソースのたまり */
```

新しい色を足すときも、どこかの `samples/*.js` から拾ってください。

## サンプル 13 本

`samples/` 以下。同じ枠組みで書かれていますが、担当する「難所」が 1 本ずつ違います。

| ファイル | そこでしか出てこない技術 |
| --- | --- |
| [トースト.js](samples/トースト.js) | 輪郭を SDF で作り、す（気泡）を彫り、焼き色を塗る。構造がいちばん素直 |
| [エッグトースト.js](samples/エッグトースト.js) | トースト.js との差分。くぼみ・卵・焼き分けの3点だけで別の料理になる |
| [たこ焼き.js](samples/たこ焼き.js) | 焼き色が形と相関する話の本命。ソースは実体、青のりは板ポリゴン、物理は使わない |
| [唐揚げ.js](samples/唐揚げ.js) | 衣の粒立ちと、揚げ色の頂点カラー焼き込み。山積みは Havok で1個ずつ落として解決 |
| [ウィンナー.js](samples/ウィンナー.js) | 弓なりの掃引と、端の結び目のひだ。当たり判定を凸包からカプセル列へ直した記録つき |
| [焼き魚（サンマ）.js](samples/焼き魚（サンマ）.js) | 実写に寄せた10項目の修正がそのまま残る。銀は metallic ではなく虹彩（薄膜干渉） |
| [焼き魚（鮭）.js](samples/焼き魚（鮭）.js) | 切り身。筋節の場を作って断面に出す。皮まで含めて1メッシュ |
| [ご飯.js](samples/ご飯.js) | 約1400粒を1粒ずつ置く。説得力を決めるのは粒間の暗がりで、配置時に焼き込む |
| [お寿司.js](samples/お寿司.js) | ご飯.js の続き。ネタは表面ではなく包丁の切り口。霜降りは色ではなく実体 |
| [クッキー.js](samples/クッキー.js) | 7種を断面と外形の数値だけで作り分ける。工業製品なので乱数の幅が狭い |
| [チョコレート.js](samples/チョコレート.js) | 外形（スーパー楕円）× 縦断面。ブルームと櫛目。Havok で1粒ずつ落とす |
| [花見団子.js](samples/花見団子.js) | たれは色ではなく層（吸収で解く）。串の入口はすり鉢状にへこむ |
| [月見団子.js](samples/月見団子.js) | 接触変形。潰した体積の行き先と、接触の縁にできる丸い土手 |

どのファイルも先頭に「構成」というコメントがあり、`0. CONFIG` → `1. Rng` → `2. Noise` →
`3. Mesh utils` → `4. Fields / Section / Shape` → `5. TextureLab` → `6. 本体` →
`7. 皿・板・トレイ` → `8. Scene / 物理` → `9. GUI` の順に並んでいます。

コメント中の **【対策】** は「一度失敗して直した記録」です。なぜその数値なのか、
なぜその順番なのかは、たいていそこに書いてあります。

## 章立て

### 第I部 — 1皿をつくる（00〜11）

1本の .js ファイルを、上から順にほどいていく構成です。

| | 章 | 内容 |
| --- | --- | --- |
| 00 | まず動かしてみる | インストールなし。ブラウザだけで13本を動かす手順 |
| 01 | 手続き生成 | モデルも写真も読み込まず、実行した瞬間に座標と模様を計算で作る |
| 02 | 乱数 | `Math.random()` を使わない理由。種を渡すと毎回同じ結果になる乱数を書く |
| 03 | ノイズ | となり合う値がなめらかにつながる乱数。重ねると焼きムラや生地の肌理になる |
| 04 | かたち | 断面を1枚描いて軸のまわりに回す。回らないものは外形×縦断面で作る |
| 05 | 面と法線 | 3Dモデルの正体は座標の配列と三角形の番号表。裏返ると立体が消える理由 |
| 06 | テクスチャ | UVで立体と画像を対応させ、模様を1ピクセルずつ計算で描く（色・粗さ・凹凸の3枚） |
| 07 | PBR | 「照っている」「ぬれている」を数値で書く。粗さ・クリアコート・透け |
| 08 | 物理 | 皿への盛り付けは手で置かない。重力と摩擦を与えて Havok に任せる |
| 09 | 部品 | 青のりもかつお節も、テクスチャに描くと消える。実体のかけらとして撒く |
| 10 | 曲がり | 先に軸を決め、断面を軸に垂直に置いていく（掃引） |
| 11 | 光 | 同じ料理でも光で別物になる。IBL・影・露出・トーンマッピング |

### 第II部 — 火が通ったものをつくる（12〜17）

野菜編では出てこなかった、料理だけの 6 つの難所。

| | 章 | 内容 |
| --- | --- | --- |
| 12 | 焼き色 | 焼き色は最後に塗る飾りではない。形と結びついていないと「汚れ」に見える |
| 13 | たれ | たれを茶色く塗ると光沢のない卵になる。色は厚みから解くもの（`exp(-係数×厚み)`） |
| 14 | 透け | 透けを切ると、白玉は石膏に、赤身は消しゴムになる。厚みを持たせる |
| 15 | 粒 | 茶碗一杯は約1400粒。説得力を決めるのは粒間の暗がりで、SSAOでは出ない |
| 16 | 潰れ | 団子は真球では積めない。潰した体積の行き先と、接触の縁の土手 |
| 17 | 差分 | トーストとエッグトーストは同じプログラム。色を変えただけでは別物にならない |

各章には **その場で動かせる実験** が 1 つずつ入っています（全 17 個）。
外部ライブラリは使わず、Canvas 2D の上にミニチュアのレンダラを組んであります。

## サムネイルの収録

```sh
node tools/shoot.js            # 13本ぜんぶ
node tools/shoot.js トースト   # 名前で絞り込み（部分一致）
```

ヘッドレスの Chrome を DevTools プロトコルで動かし、**サンプルを実際に実行して撮ります**。
生成物は `assets/thumbs/` に入り、リポジトリに入れて配ります。

1. ローカルに HTTP サーバを立てる（`file://` だと WebGL も CDN も面倒）
2. Chrome を `--headless=new --use-angle=swiftshader` で起動（GPU が無くても描ける）
3. `createScene()` の完了を待ち、**メッシュが増えず・動かなくなる**まで待つ
   （固定時間で待つと、唐揚げが宙に浮いた絵で撮れる）
4. 待つあいだは 1/6 解像度・影と後処理オフで回し、撮る直前に等倍へ戻す
5. GUI（右下のスライダー）だけ隠し、描かれた画素から被写体の枠を求めて切り出す

環境変数: `SHOOT_DEBUG=1`（各段階の所要時間と切り出し枠）、`SHOOT_DUMP=1`（メッシュ一覧）、
`SHOOT_BUILD_TIMEOUT`（組み立て待ちの上限 ms、既定 600000）。

再収録が要るのは**サンプルの見た目を変えたときだけ**です。

```sh
node tools/verify-play.js      # play.html で 13 本が本当に動くか
```
